# 第二版批量采样设计：固定条件下生成 10 万副牌

用户的主要场景是限制 1～2 家的牌型和 HCP，在同一组条件下均匀、有放回地采样 100,000 副完整牌局。枚举接口仍须不重不漏。

设计调整为：条件编译一次，联合抽取受约束的玩家，再把余牌均匀分给其他玩家。完整四家牌型矩阵不再是默认批量采样的外层状态。

本次交付包含数学设计、研究原型和实测记录；尚未替换第一版生产后端。

2026-10-20 更新：[固定手牌三项目标实验](v2-target-experiment.md)已新增可选 `--backend v2`
及 `compile_sampler()` / `sample_batches()`。该实现覆盖已知牌与牌型条件；
本文的 HCP 联合计数原型及自动策略选择仍未接入该接口，默认后端仍为 v1。

## 1. 为什么批量场景需要调整

上一版单次 SAMPLE 的流式加权选择，每抽一副都可能重新扫描所有牌型并计算权重。如果循环调用 100,000 次，就会重复支付相同的预处理成本。

批量接口应当是：

~~~text
plan = COMPILE(conditions)
batch = plan.SAMPLE_MANY(count=100000, seed=20260922)
~~~

目标函数是：

\[
T(N)=T_{\rm compile}+N\,T_{\rm draw}+T_{\rm output},\qquad N=100000.
\]

一次性构建计数表和转移表，后续每副牌只做整数加权选择、零点牌分配和余牌分配。全部候选顺序和随机算法固定。

## 2. 只对真正受约束的 1～2 家做联合计数

令 \(A\) 为受牌型或 HCP 条件约束的玩家，\(k=|A|\in\{1,2\}\)；其余玩家集合为 \(U\)。

已知具体牌仍可出现在任何玩家手中。首先从公用牌堆中移除所有已知牌，保留其固定归属。

令每家已知牌数为 \(f_p\)，还需补入的张数为：

\[
m_p=13-f_p.
\]

当 A 中的每一家都已经完成持牌后，留给 U 的未固定牌总数是常数：

\[
M=\sum_{u\in U}m_u.
\]

不论 A 中具体拿到了哪些合法牌，余牌分给 U 的补全数都相同：

\[
\boxed{
R=\frac{M!}{\prod_{u\in U}m_u!}.
}
\]

因此只要均匀选择 A 的合法、互不冲突的联合持牌，再将剩余未固定牌均匀分给 U，最终完整牌局就是均匀的。

这里要求 U 中没有尚未处理的牌型/HCP 限制；具体已知牌已经提前移除，允许存在。

对于两家受约束玩家，必须进行联合计数，以同时处理牌张冲突和条件相关性。

## 3. 将原来的四家大牌归属改为“受约束玩家 + 余牌池”

每张未固定的大牌只需选择属于 A 中某家，或者属于余牌池 \(*\)。

每门花色有 \(u_s\le4\) 张未固定的大牌，因此候选数是：

\[
(k+1)^{u_s}.
\]

| 受约束玩家数 | 每门花色最多大牌候选 |
|---|---:|
| 1 家 | \(2^4=16\) |
| 2 家 | \(3^4=81\) |
| 原四家归属模型 | \(4^4=256\) |

第一层也只选择 A 中各家的有序牌型：

\[
\Lambda=(\lambda_{as})_{a\in A,s\in S}.
\]

不指定其他玩家的具体牌型，直接通过余牌池补全。

例如 N 指定有序 5431，S 指定无序 4333：只需考虑 \(1\times4=4\) 个受约束玩家牌型组合。

若两家都指定无序 5431，最多是 \(24\times24=576\) 个组合，再剔除不兼容者。这只是常见单个无序牌型的规模；任意牌型并集可能更大，不能套用这个上界。

## 4. 缩减后的局部权重

沿用每家每花色的已知牌数 \(f_{as}\)。设该花色未固定的零点牌数为 \(z_s\)。

对一个未固定大牌归属方案 \(\psi_s\)，定义：

\[
g_{as}=\#\{r:\psi_s(r)=a\},
\]
\[
q_{as}=q^F_{as}+
\sum_{\substack{r\ {\rm 未固定}\\\psi_s(r)=a}}v(r),
\]

其中 \(q^F_{as}\) 是该家该花色已知大牌的 HCP。

各家还需要的零点牌数为：

\[
r_{as}=\lambda_{as}-f_{as}-g_{as}.
\]

这里 \(f_{as}\) 包括已知大牌和已知零点牌，\(g_{as}\) 只统计未固定大牌，避免重复扣除。

余牌池的零点牌数为：

\[
r_{*s}=z_s-\sum_{a\in A}r_{as}.
\]

若任意 r 为负，该方案无效。否则：

\[
\boxed{
w_s(\Lambda,\psi_s)
=
\frac{z_s!}
{r_{*s}!\prod_{a\in A}r_{as}!}.
}
\]

只计受约束玩家联合持牌的数量：

\[
\boxed{
D(\Lambda)=
\sum_{\psi\ {\rm 满足\ HCP}}
\prod_s w_s(\Lambda,\psi_s).
}
\]

令 \(D=\sum_\Lambda D(\Lambda)\)，则完整牌局总数为：

\[
\boxed{C=D\,R.}
\]

抽取受约束玩家牌型组合时使用 \(D(\Lambda)/D\)。常数 R 不影响这一选择。

## 5. HCP 后缀 DP 只跟踪 1～2 家

对固定 \(\Lambda\)，令 \(\mathbf t\) 为受约束玩家的累计 HCP。终止和递推为：

\[
B_4(\mathbf t)=
\mathbf1\{\mathbf{low}\le\mathbf t\le\mathbf{high}\},
\]
\[
\boxed{
B_j(\mathbf t)=
\sum_{\psi_s}
w_s(\Lambda,\psi_s)
B_{j+1}(\mathbf t+\mathbf q_s),
\quad s=s_{j+1}.
}
\]

于是 \(D(\Lambda)=B_0(\mathbf0)\)。

- 一家只保存一个 HCP 坐标。
- 两家只保存两个 HCP 坐标。
- 不需要跟踪余牌池的 HCP。
- 同一个 HCP 向量下的候选可合并用于计数，但抽样表保留具体大牌归属。
- 各家的已知大牌点数已经在各花色 q 中，因此仍从零点向量开始。

两家时，处理 j 门完整花色后的点数状态，忽略其他限制，有安全上界：

\[
|\mathcal Q_j|\le\binom{10j+2}{2}.
\]

j=0,1,2,3 时分别为 1、66、231、496；每个具体牌型组合的宽松转移上界为：

\[
81(1+66+231+496)=64\,314.
\]

一家对应的宽松转移上界为：

\[
16(1+11+21+31)=1024.
\]

实际还会被牌型容量、HCP 区间和已知牌进一步压缩。

## 6. 编译阶段和批量抽样阶段分开

~~~text
function COMPILE(conditions):
    C = NORMALIZE(conditions)
    active = 找出有实质牌型或 HCP 限制的玩家
    inactive = 其余玩家
    移除全部已知牌并保存固定归属

    if active 为空:
        return UNIFORM_REMAINDER_PLAN(C)

    if active 中没有任何牌型限制:
        return COMPILE_HCP_GROUPS(C, active)

    if 受约束玩家牌型组合的预计规模超过预算:
        return BUILD_EXACT_REJECTION_PLAN(C)

    for 每个兼容的受约束玩家牌型组合 Λ:
        构造每门花色的大牌候选及零点牌组合权重
        计算后缀计数 B
        if B(0, 0) > 0:
            保存 Λ 的权重 D(Λ)
            编译每个非零状态的整数累积权重表

    编译 Λ 的整数累积权重表
    准备零点牌分配小表、余牌分配参数、版本信息
    return immutable CompiledSampler


function SAMPLE_MANY(plan, count, seed):
    rng = 新建固定算法和版本的随机数生成器(seed)

    repeat count times:
        Λ = 按 D(Λ) 选择受约束玩家牌型组合
        points = 零向量

        for 每门花色 s:
            ψ = 按 w_s * B(next, points + q_s) 选择具体大牌归属
            从该方案的零点牌分配小表中均匀选择一项
            更新受约束玩家的实际持牌
            points += q_s

        remaining = 除去全部已知牌及已分配牌后的未固定余牌
        将 remaining 均匀分给其他玩家，补齐各自所需张数
        yield 完整牌局的独立快照
~~~

生产批量接口可流式输出分块；研究原型直接返回 \(100000\times4\) 的 uint64 位图数组。

预处理期间计算状态数量、总权重、CDF；抽样热循环不反复计算阶乘、不遍历所有候选以重新求权重，也不在每次调用时重建 DP。

## 7. 零点牌小表很小，可以复用

每门花色至多 9 张未固定零点牌。它们对“k 家 + 余牌池”的全部分配总数是：

\[
(k+1)^9.
\]

按每组张数向量 r 分桶，桶内每个实际分配存为各组的位掩码。抽样时用无偏整数选一个下标。

| 受约束玩家 | 全部分配数 | 每项存每组一个 uint16 的原始数据量 |
|---|---:|---:|
| 1 家 + 池 | \(2^9=512\) | 2,048 字节 |
| 2 家 + 池 | \(3^9=19,683\) | 118,098 字节 |

有已知零点牌时使用 z<9 的表，并将位置掩码映射回实际牌点。包括所有 z=0..9 的两家表，原始位掩码总量也只有 177,144 字节；容器、索引和其他缓存另计。

最后分给其他玩家的 26 或 39 张余牌使用均匀部分洗牌/选子集，不预存其全部组合。

## 8. 只限 HCP 时改用点值分组

没有任何牌型条件时，先按花色展开牌型会引入无用状态。

移除已知牌后，对 v=1,2,3,4，设 n_v 为该点值尚未固定的牌数，最多 4 张。令 x_(a,v)、x_(*,v) 为分配给受约束玩家及余牌池的张数：

\[
x_{*v}+\sum_a x_{av}=n_v.
\]

每组点值的分配数权重为：

\[
\frac{n_v!}{x_{*v}!\prod_a x_{av}!}.
\]

设自由零点牌总数为 z，受约束玩家的零点牌需求为：

\[
r_a=m_a-\sum_vx_{av},\qquad r_*=z-\sum_ar_a.
\]

检查 HCP：

\[
low_a\le q_a^F+\sum_vv\,x_{av}\le high_a.
\]

整个类别方案的权重是：

\[
\boxed{
W=
\left(\prod_{v=1}^{4}
\frac{n_v!}{x_{*v}!\prod_a x_{av}!}\right)
\frac{z!}{r_*!\prod_a r_a!}.
}
\]

一家受约束时，最多只有 \(5^4=625\) 个点值张数方案；两家时，最多：

\[
\binom{6}{2}^4=15^4=50\,625.
\]

按 W 编译分布，再均匀恢复具体大牌身份、分配零点牌和其他玩家余牌。该特化已经给出计数模型，但尚未包含在此次性能原型中。

## 9. 条件较宽或牌型集合很大时使用精确拒绝采样

常见 1～2 家的明确牌型与 HCP 采用上述联合编译。其他情况由编译器选择：

| 条件结构 | 优先路径 |
|---|---|
| 只有已知牌，没有实质牌型/HCP 限制 | 直接均匀补齐余牌 |
| 1～2 家明确牌型，加 HCP | 联合计数并编译转移表 |
| 只有 1～2 家 HCP | 点值分组编译 |
| 牌型并集很大、部分玩家只限 HCP 等混合条件 | 比较编译规模与精确拒绝采样成本 |
| 3～4 家受约束 | 使用更一般的计数/采样路径，单独设预算 |
| 完整枚举 | 保留原三层流式遍历 |

拒绝采样可以从已经满足部分条件的均匀分布开始。例如先均匀满足牌型，再检查 HCP；零点牌身份和无约束玩家可以尽量推迟到接受后才生成。

拒绝时必须重新抽取整个候选。不能固定一个按无 HCP 权重选出的牌型，然后在该牌型内部一直重试到点数成功，那会改变最终牌型的概率。

设 p 为条件接受率，t_prop 为候选成本，t_finish 为接受后补全成本：

\[
T_{\rm reject}(N)
\approx T_{\rm base}+
N(t_{\rm prop}/p+t_{\rm finish}).
\]

与：

\[
T_{\rm compiled}(N)
\approx T_{\rm compile}+N\,t_{\rm draw}
\]

比较。相同条件下生成 100,000 副，通常值得承担比单次发牌更多的编译工作，但不应无限制构建状态表。

编译预算超限时，应切换到覆盖完整合法空间的后备算法；不能只对已经编译的部分牌型重新归一化并输出样本。

如果使用校准采样选择策略，校准应使用独立随机流；记录选中的执行计划和算法版本，避免策略变化破坏结果复现。

## 10. 本机实测

环境：Python 3.12.6、NumPy 2.5.3、macOS arm64。研究原型的采样循环以 Python 为主，使用 NumPy 存储小表和输出位图。

| 条件 | 受约束玩家牌型组合 | 编译时间 | 生成 100,000 副 |
|---|---:|---:|---:|
| N 有序 5431，12～16 HCP | 1 | 0.064 秒 | 4.022 秒 |
| 上述 N；S 无序 4333，8～12 HCP | 4 | 0.522 秒 | 2.884 秒 |

测量范围：

- 包括全部四家的实际牌张生成。
- 输出为内存中的四个 uint64 持牌掩码，共 3,200,000 字节。
- 不包括 PBN/JSON 文件导出，也不包括 DDS。
- 单次本机测量，是这两个具体条件的结果，不是所有条件的性能保证。

两组各 100,000 副均逐副通过：

- 每家 13 张；
- 全副 52 张牌完整且不重复；
- 指定牌型和 HCP 条件；
- 相同种子重跑，前 256 副完全一致。

另外完成 3 个独立闭式计数检查，以及 2 个带已知牌的小空间 CP-SAT 交叉检查：完整牌局计数分别为 180 和 12，与第一版一致；各检查了 1,000 副样本。

正确性依据是分层计数和均匀恢复的数学证明，合法性检查与计数交叉验证是实现证据；有限样本频率本身不能证明严格均匀。

精确计数还给出了“从完全随机牌局开始拒绝”的接受率：

| 条件 | 接受率 | 取得 100,000 副的期望候选数 |
|---|---:|---:|
| 上述一家条件 | 0.15345% | 约 6,517 万 |
| 上述两家条件 | 0.007088% | 约 14.11 亿 |

这是期望尝试次数，不是旧实现的实测完成时间。

若已经先满足牌型，再过滤 HCP，两组接受率分别约为 28.48% 和 12.75%。因此“先满足部分条件再拒绝”也能显著改善原来的全副洗牌方案；默认批量方案进一步复用精确后缀计数。

第一版另做了 20,000 次尝试预算的短探测。首次 endplay 导入触发了 Matplotlib 字体缓存初始化，其耗时不适合作为稳定吞吐率对比，结果文件明确标注了这一点。

## 11. 建议接口与落地顺序

~~~text
plan = compile_sampler(
    conditions,
    expected_count = 100000,
    distribution = "uniform_with_replacement",
    strategy = "auto"
)

for chunk in plan.sample_batches(
    count = 100000,
    seed = 20260922,
    batch_size = 4096
):
    consume(chunk)
~~~

计划对象保存：

- 规范化条件和指纹；
- 所选策略、受约束玩家集合；
- 非零牌型组合及权重；
- 每个可达状态的大牌候选、后缀计数和整数 CDF；
- 零点牌小表与已知牌映射；
- 随机算法及实现版本。

种子属于采样调用，同一计划可用于多个种子。固定 seed 连续生成 100,000 副，应与分块生成后拼接的序列一致，不应每个块都重置同一种子。

优先落地：

1. 将本次验证过的 1～2 家明确牌型/HCP 联合编译做成正式后端。
2. 加入仅 HCP 的点值分组特化。
3. 加入有预算的策略选择和精确拒绝采样后备路径。
4. 分别测量生成、序列化和 DDS 耗时，再决定是否将热循环移到 C++/Rust。
5. 保留枚举接口，独立测试其不重不漏性质。

若后续并行采样，应按样本索引派生确定的随机流，或使用确定的分块顺序；不能让工作线程完成顺序决定随机数流和输出顺序。

研究原型：research/v2_batch_sampling_probe.py
实测结果：artifacts/v2-batch-sampling-probe.json
该原型支持 1～2 家明确牌型及 HCP 和任意玩家已知牌；完整策略选择器、HCP-only 特化、生产批量接口尚待实现。
